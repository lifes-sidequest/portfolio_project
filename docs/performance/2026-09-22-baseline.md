## Loader and initial animation audit

The visible loader interval was profiled separately from initial navigation. Across an approximately 2.3-second display, loader-time JavaScript used 9 ms on desktop and 10 ms on mobile; layout work used 10 ms and 7 ms respectively. The greeting interval produces only a few React updates, and the curtain animation uses a compositor transform. No visual simplification was justified by this measurement.

After the loader, a two-second idle sample used 16–23 ms of task work with zero or one layout. Both project-card videos were already paused by the browser after scrolling them offscreen, so replacing their current behavior would not provide a demonstrated CPU improvement.

Character reveal animations originally retained `will-change: filter, opacity` after completing. Depending on the route, 82–99 finished character spans kept those compositor hints active, contributing to 127–138 hinted elements in total. The shared reveal controller now releases each hint on the existing `blur-reveal` animation-end event. Repeated desktop and mobile measurements found zero remaining character hints and 39–45 hinted elements in total after animation completion. Static About and Car Parts screenshots remained byte-for-byte visually equivalent; the home comparison differed only because its project videos autoplay.

Scroll-reveal sections also previously retained `will-change: opacity, transform` while waiting far below the viewport and after their transition completed. The hint is now applied one animation frame before an intersecting section begins its existing transition, then removed on `transform` transition-end with a 900 ms fallback for media elements whose transition event may be skipped. Initial hinted elements fell again to 21–24 across the measured routes. On desktop and mobile Car Parts, 8–11 hints were present only during the reveal and returned to zero scroll-reveal hints after settling.

Hover-only navigation, social-folder, and certification-arrow elements also retained compositor hints while idle. Their base states now use `will-change: auto`, and the original hints are restored only while the relevant control is hovered or keyboard-focused. The settled home and About pages now retain 3 hints instead of 23–24; these belong to the fixed header and custom cursor. Car Parts retains 13 instead of 21, including the 10 GSAP-controlled fan cards. A folder temporarily activates its 4 existing hints during hover and returns to zero hover-only hints when the pointer leaves; the desktop navigation similarly activates only the 2 text layers belonging to the hovered link. The About viewport was visually compared with the previous approved capture and showed no visible layout or styling change.

## Inspiration stamp artwork

A route-by-route production profile identified `/inspiration` as the remaining static-image outlier: it transferred approximately 5.9 MB and produced one 73 ms long task, while the other non-case routes transferred roughly 0.45–2.56 MB with no recorded long tasks. The causes were the 2.8 MB front PNG used again as a CSS mask and a path-heavy 6.4 MB back SVG that transferred 2.2 MB and decoded to 6.5 MB.

The front and back now use visually reviewed WebP derivatives of 344 KB and 57 KB while retaining their original 1536×1024 and high-density 956×500 render sizes. The front uses one direct URL for both the visible image and CSS mask, so the second mask request is served from cache with only a 300-byte request entry instead of downloading a separate Next.js image derivative. The route now transfers approximately 954 KB in the same profile and records no long tasks. Flip, pointer motion, perforated mask, and both color themes were checked in the production build; original source artwork remains retained.

The Caveat face used only by the English and German flip hints was also subset into a local WOFF2 while retaining the original TTF. Its browser transfer fell from approximately 128 KB to 9 KB, and the route profile fell again to approximately 835 KB. Both localized hints were visually checked for matching letterforms, spacing, rotation, and single-line layout.

The expanded 12-run Lighthouse gate measured median performance scores of 0.96 for Home, 0.99 for About, 0.98 for Inspiration, and 0.95 for Car Parts. Every route scored 1.00 for accessibility, best practices, and SEO, with 0 ms TBT. Inspiration measured a 984 ms LCP and 0.0004 CLS. Its stamp flip, both localized hints, and reduced-motion behavior are also covered by production E2E tests on desktop and mobile.

## Final CSS and client-boundary audit

The 778-line site stylesheet contains no repeated exact selectors outside the intentional responsive media-query blocks. The remaining global rules describe shared theme tokens, page-specific layouts, interaction states, and animations; mechanically converting them to utilities or deleting viewport-inactive rules would add regression risk without a demonstrated runtime benefit.

The route-level client boundaries are currently justified by shared live preferences (English/German and light/dark themes), the minute clock, or route-specific interactions and deferred media. Production chunks remain small and route-scoped, with GSAP isolated to Car Parts. A server/client split of those pages was therefore not pursued: it would increase component boundaries and hydration coordination without addressing a measured CPU, transfer, or long-task problem.
